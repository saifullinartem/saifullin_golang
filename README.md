# TripGo

Сервис поездок для курса «Разработка микросервисов на Go».

## Лабораторная 1

Сервис создаёт поездки, возвращает их по ID и завершает. Поездки и история
статусов хранятся в PostgreSQL; для них есть две миграции и отдельные репозитории.

HTTP-сервер работает на chi. Типы ответов и серверные интерфейсы генерируются
из OpenAPI. Настройки читаются из окружения. При остановке сервер ждёт завершения
активных запросов в пределах заданного таймаута (graceful shutdown).

## Запуск

Для запуска нужны Docker, tripgoctl и Go 1.26+.

```bash
tripgoctl cluster start
tripgoctl environment start
tripgoctl connect

make migrate
make run
```

В `.env.example` указаны настройки сервиса и пула соединений. Команда tripgoctl
создаёт `.env` с реальным `DATABASE_URL`, который заменяет пример адреса базы.
Файл `.env` не коммитится.

`make run` загружает сначала `.env.example`, затем `.env`, поэтому значения
из `.env` имеют приоритет.

## HTTP API

`/health` возвращает `200` и `{"status":"ok"}` без обращения к базе.
`/ready` проверяет PostgreSQL и возвращает `200` с `ok` либо `503` с `unavailable`.
Если база недоступна при запуске, сервис не стартует.

| Операция | Запрос | Результат |
|---|---|---|
| Создание | `POST /api/v1/trips` | `201` и поездка; `Location` указывает на её адрес |
| Получение | `GET /api/v1/trips/{tripId}` | `200` и поездка либо `404` |
| Завершение | `POST /api/v1/trips/{tripId}/finish` с пустым телом | `200` и завершённая поездка; при повторе `409` |

Форматы запросов и ответов описаны в
[OpenAPI-контракте](contracts/openapi/trip-service.openapi.yaml).
Ошибки возвращаются как `application/problem+json`, успешные ответы
как `application/json`. У одного водителя может быть только одна активная поездка.

## Команды

`make generate` заново генерирует API из контракта.

`make migrate-down` откатывает последнюю миграцию. Чтобы откатить обе миграции,
нужно вызвать команду дважды. При откате таблицы удаляются вместе с данными.

`make test` выполняет `go test -race ./...`. Отдельных тестовых файлов в первой
лабораторной нет, поэтому команда проверяет сборку пакетов с детектором гонок.

## Настройки

Значения по умолчанию указаны в [.env.example](.env.example).

| Переменная | Назначение |
|---|---|
| `HTTP_ADDR` | адрес HTTP-сервера |
| `HTTP_READ_TIMEOUT` | таймаут чтения запроса |
| `HTTP_READ_HEADER_TIMEOUT` | таймаут чтения заголовков |
| `HTTP_WRITE_TIMEOUT` | таймаут записи ответа |
| `HTTP_IDLE_TIMEOUT` | таймаут простаивающего соединения |
| `LOG_LEVEL` | debug, info, warn или error |
| `SHUTDOWN_TIMEOUT` | время на завершение активных запросов |
| `DATABASE_URL` | строка подключения из окружения TripGo |
| `DATABASE_MAX_CONNS`, `DATABASE_MIN_CONNS` | границы размера пула |
| `DATABASE_MAX_CONN_LIFETIME` | максимальное время жизни соединения |
| `DATABASE_CONNECT_TIMEOUT` | таймаут подключения и начальной проверки базы |
| `DATABASE_QUERY_TIMEOUT` | таймаут запросов к базе и выполнения транзакции |

## Решения

Метод `Do` открывает транзакцию и сохраняет её в контексте. Репозитории
используют транзакцию из контекста, а вне `Do` выполняют запросы через пул.
При успешном выполнении менеджер делает commit, при ошибке или панике
делает rollback. Ошибка или паника передаётся вызывающему коду.

Для rollback используется отдельный контекст с таймаутом. Он позволяет
откатить транзакцию даже после отмены HTTP-запроса. Вложенный `Do` для того же
пула использует уже открытую транзакцию.

Создание или завершение поездки и запись истории выполняются в одной транзакции.

При открытии транзакции явно задаётся уровень изоляции `Read Committed`.
Для текущих операций его достаточно: частичный уникальный индекс не позволяет
создать две активные поездки одному водителю, в том числе при параллельных
вставках.

Завершение выполняется одним UPDATE с условием `status = 'active'`, поэтому
повторно завершить поездку нельзя. Если UPDATE не изменил ни одной строки,
репозиторий читает поездку, чтобы отличить отсутствующую от уже завершённой.

Все SQL-запросы репозиториев собираются через squirrel с плейсхолдерами `$N`.
Ошибка PostgreSQL `23505` на индексе `trips_active_driver_idx` преобразуется
в `ErrDriverBusy`. Остальные ошибки передаются без такого преобразования.
